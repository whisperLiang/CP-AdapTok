# ub-mode 操作记录

| 阶段 | 执行与证据 |
|---|---|
| 分支和磁盘审计 | 对照本地、远端和工作树的 Git 身份，核验待删工作树的未提交差异、软链接、子模块、进程占用和共享权重。先保存保留资产 SHA256 与目标 inode 清单。 |
| 原始基线冻结 | 在原始 PHT-Tok 提交重放 174 帧 Validation，分别重放 PHT1 MASK 和 PRECISION 的独立合法前缀，比较原生 Y/Z 符号、像素、参考与性能。 |
| 安全清理 | 删除确认退役的三个实验工作树、四个本地分支和 AIP 专属物理文件。复核公共资产和主分支 Git 身份，保留公共 Git 对象。 |
| 测试先行 | 先以新的八档 wire/索引测试复现旧实现缺少 PHT2 的失败。加入实际 rANS 记录、预算对齐、增量 offset 和位置校验。 |
| LD 严格回归 | 比对三个独立端的原生缓冲和整数。发现 LD 的 I 特征占用共享 scratch，经实例私有分配修复。重编后在跨参考刷新样点保持零容差。 |
| 研究验证 | 运行四档 QP 和八档前缀，分别比较完整原生参考与固定最低层闭环。独立官方扩展校验实际码流和重建哈希。 |
| 运行时与动态 | 以同一段 UVG 的稳态帧执行同步计时。初次动态回放暴露 Oracle 预解独立 I 后重复提交的问题。独立 I 单元只有一档，选择时无需预解，修复后另跑同一套轨迹。 |
| 质量审计 | 复测 CPU/CUDA、定向变异、Ruff、mypy、Dryer 和 Crapper。按 GPU、字节和质量证据分别记录通过项和未达门槛。 |
| 实物交付 | 保存真实码流长度、图表及绘图质量审计，记录容器约定、复现命令和 SHA256 清单。 |
