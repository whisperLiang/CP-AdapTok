# 统一渐进编解码器

正式输入保持原生 1920×1080。共享层执行一次分析、一次完整打包、固定字节前缀选择、分段接收和参考提交。LD 与 HT-S 分别拥有原生 CUDA 图、量化参数、上下文、空间掩码、合成和参考张量。主分支的既有研究快照与此分支的 Git 历史均可供追溯。

| 位置 | 职责 |
|---|---|
| `baselines/dcvc_uf/native.py` | 官方权重、原生 I/P 输入、压缩与重建 |
| `pht_tok/official_adapter.py` | 官方 LD、HT-S 原生符号与参考状态 |
| `pht_tok/codec.py` | 分组符号、一次编码、逐层解码、参考提交 |
| `pht_tok/entropy.py` | 官方 CDF 的独立 rANS 记录，原有 P2 条件精度细化 |
| `pht_tok/bitstream.py` | 容器版本、CRC、合法边界和可重放增量读取 |
| `pht_tok/api.py` | 面向 RGB 的 `PHTTok` 与 `DecodeResult` |
| `experiments/pht_tok/evaluate.py` | 原生对照、Validation、运行时和动态回放 |

## 原生计算和渐进组织

LD 的超先验整数 Z 和时间记忆给出共同先验与高斯 CDF 索引。Y 有两组官方空间掩码，第二组的合成均值依赖第一组已恢复的残差。PHT2 按原生掩码次序，每个掩码保留原 NHWC 坐标顺序并轮流分给四个记录。各记录用官方 CDF 实际熵编码。渲染在未到达位置以条件均值完成合成，固定参考照此生成。继续收到增强时，更新显示层的完成结果。

HT-S PHT1 按原四掩码顺序。原 P2 保留四档条件精度。PHT2 将每个 PHT1 掩码按原顺序交错成两个记录，顺序仍服从原空间先验。四档 PHT1 与八档 PHT2 共用容器解析和增量接收。HT-S 的原生八帧联合计算需要采满一个 Chunk，LD 使用单帧参考时序。

## 两种参考模式

完整原生参考使用全部八层形成参考，并验证两个独立端的状态张量与官方解码一致。可变前缀闭环在实验中固定用第一层作为跨单元参考，后续层增强显示。闭环的 Full 重建使用一路生成的历史状态，所以其率失真与官方完整参考分别核算。丢失必要参考层后，依赖单元会被拒绝，独立 I 单元可建立新参考。

LD 原生代理曾从共享 scratch 池取得长期 I 特征。多个实例同时存在时，显示重建会覆盖其他实例的该缓冲。双后端扩展给每个 LD 代理分配独立 I 特征，沿用原有分析、先验和合成 CUDA 运算。官方源码由固定子模块提供，扩展变更应用在构建副本。

正式模型没有追加训练和优化器更新。Validation 数据划分、帧顺序、指标权重及原始 PHT-Tok 容差均按照冻结记录核对。 [基线冻结](../baseline_replay/freeze.json)
