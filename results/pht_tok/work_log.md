# PHT-Tok 工作日志

| 阶段 | 操作与原因 |
|---|---|
| 审计 | 核对历史分支实际名称、提交和原报告哈希，基于含官方审计工具的 e90ceda 创建独立 PHT-Tok 工作树。 |
| 冻结 | 固定原生分辨率、八帧规格、五组 QP、数值容差、物理率和吞吐门槛。以尾帧和源帧率账本单测验证起步。 |
| 基线 | 校验四份官方 UF 权重，重跑原始官方入口。与历史 60 份码流逐字节复核。下载并校验 UVG ShakeNDry，补充官方 YUV420 实测。为独立 RT 构建副本修正一处 ABI 模板约束，完成官方 RT 权重对照。 |
| 接管 | 新增原生诊断入口。发现不同 HT-S 代理共用仍在使用的中间缓冲，隔离分配并重跑 80 块完整对照。 |
| 渐进 | 实现 P1 掩码和 P2 嵌套细化、独立熵编码结束状态、CRC 前缀解析、增量接收及完整码流账本。使用四段 Calibration 的真实字节筛选。 |
| 闭环 | 用独立发送和接收代理运行 UVG 的 16 个连续 P 块。比较 R1 三档参考并重放预算、丢失、迟到、版本错误及刷新情形。 |
| 优化 | 并行提交官方 rANS，重用原生 CUDA Graph 与同级 Decoder 特征。使用相同输入和硬件重测 Base/Mid/Full 与逐次显示。 |
| 网络 | 先定位开发探针中贪心 QP 导致的积压，再令两种自适应编码统一受发送节奏约束。确认估计只使用过去到达的反馈和本地积压预测。用固定版本的公开 LTE 迹及合成轨迹重新测量。 |
| 冻结验证 | 只读重放 174 帧 Validation。验证解释限定为对冻结候选的一次测量，数值门槛沿用冻结记录。Test 元数据仅用于名单与哈希隔离。 |
| 交付 | 导出逐帧、逐块、字节和性能证据。运行 CPU/CUDA 回归、静态检查、定向变异和渲染审计。使用小步本地提交保留实验过程。 |
