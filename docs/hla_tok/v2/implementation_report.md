# HLA-Tok V2 实施与验证记录

| 顺序 | 实施内容 | 理由与验证 |
|---|---|---|
| 1 | 从 `7c15849` 建立独立 worktree 和 `experiment/hla-tok-v2`，核验旧检查点、数据清单、官方源码和权重。 | 复用原 174 帧群组、指标权重和码率定义。旧资产以 SHA-256 和 Git 状态为准，读账本覆盖 Train、Validation 和封存的 Test。 |
| 2 | 完成旧 R0 的连续、VQ 及同权重旁路重放，增加中心化表示指标、实际 Q/K 注意力和 Token 干预。 | 按旧结果和实际载荷核对 R0。先用退化构造复现表示测试失败，再实现指标和干预，检查原样干预复现相同重建。 |
| 3 | 修正两次 D0 试跑中控制配对和码字查表布局。 | 原样连续干预使用连续参考。量化干预保留完整查表布局，避免缩短张量后改变局部散射的数值路径。保留两次试跑、调试读账本和最终配对。 |
| 4 | 训练 O0/O1 稠密旁路并完成 R1 直接投影、R2 空间锚定和 R3 Rank-Causal 实现。 | 诊断空间特征信息量，增加最小可区分的结构对照。通过固定物理前缀、Independent Receiver、序列化和梯度测试。重构后的 R0 重放与旧指标及实际字节一致。 |
| 5 | 跑完四臂 Train 单样本和四样本过拟合，再跑完四臂 Seed 1 配对连续短训。 | 各公平对照使用相同样本、Crop、增强、共享初始状态与更新次数。保留每 250 步诊断及最终完整原生 Validation。 |
| 6 | 实测四臂原生 FP32/BF16 性能，比较注意力和 Token 干预。 | H100 PCIe 串行实测 Neural Codec、Fixed13 Codec 与离线 Pipeline。跟踪权重 SHA、真实输入、显存和各模块耗时。 |
| 7 | 依据预设条件只补训 R0/R2 一次，两臂各续 1,000 步。 | 最后一个诊断区间三项指标同步改善。按检查点恢复训练并核对同样本链，保留补训前后的 174 帧真值。补训后 LPIPS-Alex 未过门槛，停止增加训练。 |
| 8 | 对同帧 FFV1 视频、原生 PNG 和逐像素裁块核对摘要，导出训练、表示、码率和时延图。 | 十个片段用 `ffprobe` 核实尺寸、帧率和逐帧计数，首帧 RGB 与 PNG 逐字节一致。图完成版面、PDF 小字及碰撞检查。 |
| 9 | 执行 CPU 回归、H100 功能验证、Ruff、mypy、定向变异、复杂度和重复检查。 | 八个变异分别在临时副本运行。`crapper` 和 `dryer` 不在环境中，使用 Radon 与覆盖率计算核心路径 CRAP，并以结构归一化后的 AST 相似度审查重复。mypy 使用仓库源码范围，跳过第三方类型存根。 |
| 10 | 复核新旧权重摘要、旧工作区状态、阶段裁决和读取账本，提交真实运行证据。 | 提交源码、配置、报告、指标、图件与重建像素裁块。权重和完整视频保存在实验 worktree。 |
