# HLA-Tok-C 浮点封包协议 v1

一个包属于一个视频流内的一帧。帧 ID 在同一流内唯一。发送端和接收端在会话开始前核对 C0 合成权重和静态排序表的 SHA-256。排序 ID 的实际映射见 `rank_order_manifest.json`，表中保留原 Rank、实际覆盖区域和逆映射。原始图像、发送端特征和未接收 Token 均不进入合成端。

## 包头与 Payload

整数按无对齐填充的小端顺序编码。包头共 28 字节。

| 字节偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 4 | ASCII 魔数 HLAC |
| 4 | 1 | 协议版本，当前为 1 |
| 5 | 1 | Wire 类型，1 为 FP32，2 为 FP16，3 为 BF16 |
| 6 | 1 | 静态排序 ID，0 至 2 |
| 7 | 1 | 向量维度，固定为 32 |
| 8 | 4 | Frame ID |
| 12 | 2 | Token offset，按向量计数 |
| 14 | 2 | 当前包中的 Token 向量数量 |
| 16 | 2 | 原生高度 1080 |
| 18 | 2 | 原生宽度 1920 |
| 20 | 4 | Payload 字节长度 |
| 24 | 4 | CRC32，覆盖包头前 24 字节及 Payload |

Payload 逐向量保存 32 个标准浮点分量的位表示。FP32 每向量 128 字节，FP16/BF16 各 64 字节。BF16 使用 16 位位模式传输。单包必须满足 `1 ≤ count`、`0 ≤ offset`、`offset + count ≤ 16320`。接收端校验枚举、几何、长度及 CRC32。CRC32 用于发现意外损坏。

## 增量与截止时间

基础包从 offset 0 开始。增强包从先前发送区间末端开始，发送新的向量区间。严格字节前缀针对相同帧、相同排序和相同浮点格式的 Payload。每个分段承担独立包头开销。

接收端缓冲未连通的增强区间，拒绝重复包、相交区间及不同帧或不同格式的包。只有从 0 开始的完整连续前缀可以解码。截止时提交当前连续前缀并丢弃未连通区间。截止后拒绝该帧新增包。C0 逐帧无历史状态，后一帧直接建立独立上下文。

## 实测边界

发送端在 GPU 上作标准 dtype 转换，保留位模式复制到 CPU，再生成真实字节。接收端在 CPU 解析和校验，按 Wire dtype 原样传到 GPU，随后转换至冻结的计算 dtype。模型权重始终保留原始 FP32 state_dict。

单包率失真的 total bytes 包含 28 字节包头。分段测试记录所有包头。无动态逐帧索引和尺度字段。排序表与模型权重是静态资产。码率按 1920×1080 有效像素和每帧一个时间单元计算。5、10、20、40 Mbps 的限额以 30 FPS 的单帧截止预算定义。

H100 串行测速从已在 GPU 上的原生 RGB tensor 开始，到 GPU 上的重建 RGB tensor 完成。实际计入 Token 往返复制、序列化和解析。GPU-only 路径也独立定时。磁盘 I/O 和外部网络等待在测时范围之外。
