# HLA-Tok-UF-V2 架构与运行边界

每帧先由锁定的 DCVC-UF-LD 或 DMCI 生成原生 Base。P 使用两阶段空间先验和原生帧历史，I 使用独立原生 Intra 码流。编码端提取当前分析 latent、Base latent 和原生步长。FP32 两级整数残差映射回同一个潜在空间。8×8 空间块与 8 通道带共用两个精化层，发送完整记录，Decoder 可从物理字节独立还原。

Anchor-Fast 读取编码端已生成的 I 重建与 P 基础特征。P 预览通过官方重建头从该特征取得，避免额外 Base 解码器。批量 CPU 分组、rANS 工作队列和增量解析保持 legacy E0 字节。严守现有 HUF1 Base 与增强记录顺序。

D1 的 P 特征来自官方 decoder 的 `m_feature_p`，并持有当前帧的 `m_ctx` 快照。原生代理维护自己的参考特征、`m_memory` 和特征刷新。I 在 `dec_1` 与原生通道量化增益之后保留独立显示特征，原生 I 像素初始化 LD 参考。D1 将 latent 残差投影并 PixelShuffle，融合 32 通道 Base 和当前 context 投影，经过两个 DepthConv blocks、零初始化残差映射和官方原生重建头。Base-only 直接返回原生帧。增强通过独立 Tensor 渲染，后续接收可追加记录并重新渲染。

P2 的冻结原生模块保持 FP16 原生代理。训练时允许有界调节 P 编码末端卷积的通道增益、P 原生超先验概率偏置及共享重建末端通道增益。真实码流验证将增益折入已有卷积、重新生成超先验整数 CDF，并在独立编解码端安装参数。帧间参考来自新候选的独立真实 Base，训练在节点间复用已核验的时间状态并停止跨节点求导。Optimization 使用原生坐标裁块和保持物理前缀选择的直通估计。

H100 原生 Base 走 FP16。D1 发布候选的显示头走 FP16，latent 精化积累为整数，恢复计算 FP32。训练增强用 BF16 AMP，概率和感知度计算用 FP32。纯 FP32 与纯 BF16 官方 CUDA proxy 无可用实现。
