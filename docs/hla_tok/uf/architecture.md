# Architecture and hypotheses

**Native reference path.** `NativeEncoder` and every `NativeDecoder` own their own CUDA stream, graph objects, and native entropy worker. The display path never writes the base reference. The pinned upstream allocator reused scratch among equal-size proxies in one process; a build-only patch separates allocations. This does not change checkpoint bytes, arithmetic, CDF rules or the official gitlink. Six held-out native I/P frames in separate unpatched processes provide the byte-for-byte parity guard. The locked application QP is shared by every enhancement budget. Base-only rendering returns the native postprocessed RGB directly, without an alternative reconstruct-and-compare tolerance.

**UF-Anchor.** A separate small pixel-unshuffle analysis measures the current RGB error relative to a locally decoded independent native base; a depthwise block and grouped residual scalar quantizer produce bounded symbols. A lightweight residual head corrects native RGB in the display branch. This is the RGB-domain implementation of the Anchor and not a learned decoder operating on official feature `f_base`; it is a comparison point for the unified implementation. Coarse and fine steps differ by two. A stable heap of eligible group/level entries ranks by estimated signal energy per coded byte; the initial estimate is not trained on oracle marginal LPIPS.

**Unified D0.** The second path takes the original normalized `y`, `y_base`, and native positive quantization scale from read-only native observers. After decoding, the observer returns independent copies of the native decoder latent and P context. The display adds a coarse/fine signed delta to that same latent in native scale, then runs the existing Intra/LD reconstruction layers in a separate PyTorch computation. No second analysis encoder and no transmitted context are used. The base retains all native spatial positions and the official intra four-mask or inter two-mask order. D0 is an untrained feasibility test, not an end-to-end trained checkpoint.

**Accounting.** `BaseCodec` means the opaque native rANS byte string. `Base` includes the application header. `Record` means one independently terminated group-level segment, not one latent scalar. `Prefix` means base plus zero or more complete, dependency-valid records. Actual application bytes exclude external file indexes, UDP/RTP/FEC and connection overhead. Native NAL baseline accounting includes the sequence SPS; HUF1 uses its own header, not nested SPS/NAL headers. Native `z` and `y` have no independent length fields; the diagnostic report does not invent an additive byte share for `z`.
