# HLA-Tok-CP 实现

C0 继续使用 R2、Anchored Query Tokenizer、Local Token Decoder 和 D0。发送端以原生 1920×1080 图像求得相同的 K16320 连续序列，然后按静态 O1 或 O2 重排。对固定 Profile，整帧投影形状固定，发送整数前缀在不同预算下具有相同的变换、计算顺序和尺度。接收端以收到的 Token 为输入，用原始 Rank 驱动标量恢复、Lift 和局部合成。原生 RGB 输出仍为 1920×1080。

Train 审计以实际位模式缓存 BF16 特征。完整空间 Rank 保留 `[帧, 135, 120, 32]`，最后一 Rank 单独保留 `[帧, 120, 1, 32]`。PCA 协方差以 96 帧拟合，保留的 32 帧来自互斥视频来源。每个 Rank 有独立协方差，低样本或相对谱秩不足时回退全局 PCA。RGB 敏感性用 Train 校准帧逐分量消融。完整 Validation 按八个预算比较投影宽度，按冻结的逐指标投票选择量化路线。标量尺度只用 Train 拟合，阈值在 Train holdout 上以归一化平方损失选择。

阶段选择按真实字节可行性、严格前缀和因果正确性、低码率 Pareto、低码率和高码率指标排序。等率控制使用同一批原生像素。Original 的 16 帧整窗从一个前向得到分组索引，真实 Fixed13 解包后合成并拼接。末窗重复最后一帧作为填充，实际码流按有效源帧均摊。

轻量路线只在达到门控条件时运行。T1 更新由 PCA 初始化的 Projection 和 Lift，使用固定尺度下的有界均匀噪声。T2 固定 Projection 和尺度，用等价硬整数前向更新 Lift。两个阶段都以真实发包验证。原始局部合成权重和 RGB Decoder 的梯度保留对输入的回传，参数冻结。预算按真实包大小映射并去重。两个初始候选使用相同种子、Train 顺序和随机分位序列。中途验证用三个视频的首、中、末帧，最终候选用完整 174 帧。实质改善按共同码率和视频来源成对裁决。T3 的准入要求残余损失有直接 Recovery 输入归因。运行轨迹由训练 JSON 和 CSV 记录。

完整 Validation 的每个设置保存实际的 Payload、包头、边信息、Padding 和总字节。所有颜色及感知指标使用历史权重和代码。复现同一矩阵需要匹配代码、模型、静态资产、精度和数据标识。Train Cache、临时矩阵分片和训练优化器权重按历史目录规则留在本地。可部署的静态 Profile 和小型入选适配资产可以随证据归档。
